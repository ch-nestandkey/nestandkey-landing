# Design Handoff — Note 9: Debrief Card Too Long (Landlords page)

**Status:** Awaiting Design decision before implementation
**Ref branch:** `main` (latest — all fixes merged as of July 2026)
**Page:** `/landlords` — `.key-brief-panel` (right side of the Key chat layout)

---

## Context

During usability testing (desktop, MacBook), the debrief card became long enough to require vertical scrolling once several fields were filled in. The card should ideally fit within the viewport without scrolling — it's a summary panel, not a form.

**Please pull the latest `main` and review the live debrief card with a full or near-full state** (all fields filled) to understand the current design in code before proposing a solution.

---

## Problem

`.key-brief-panel` stacks all captured fields vertically with `gap: 16px`. With 10–12 fields captured, the card overflows the viewport on a standard 800px-tall MacBook display. The photo uploader block (`.key-photo-block`) adds additional height.

---

## Options to evaluate

| Option | Description | Trade-off |
|---|---|---|
| **9a** | `max-height` + `overflow-y: auto` on `.key-brief-fields` | Simplest to implement; scroll inside the card feels contained but hidden content isn't obvious |
| **9b** | Two-column field layout inside `.key-brief-fields` | Fits more fields in the same height; requires label/value pairs to be compact enough |
| **9c** | Consolidate fields into fewer rows (e.g. city + neighborhood → one row; availability + min stay → one row) | Reduces row count without layout change; may lose readability |
| **9d** | Progressive disclosure — collapse filled sections, expand on tap/hover | Most elegant but adds interaction complexity and JS |

Options can be combined (e.g. 9b + 9c).

---

## Constraints

- **Mobile (≤1024px):** Single-column stacked layout; `.key-intake-wrap` is `align-items: start`. Any solution should degrade gracefully or be desktop-only.
- **JS contract:** The following classes are generated by `renderKeyBrief()` and must not be renamed: `.key-brief-row`, `.key-brief-label`, `.key-brief-value`, `.key-brief-check` (hidden via CSS), `.key-brief-row-text`. Field rows are emitted dynamically — any grouping/consolidation logic needs a corresponding JS change.
- **Photo block height is fixed** — the uploader (`key-photo-drop`) has `padding: 32px 20px` intentionally for breathing room. Don't compress it.

A Figma frame (desktop, 1280px wide) showing the preferred solution with a filled debrief card (all fields + photos added state). Include redlines or notes on any new CSS values. If 9c or 9d, note which fields to consolidate or which sections collapse.
